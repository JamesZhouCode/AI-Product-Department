## 一、系统架构总览

```
浏览器（内网用户）
   │  HTTP
   ▼
前端静态站点（React 19 SPA，Vite 构建，全部资源打包在 dist/ 内）
   │  /api/* 反向代理（开发期 Vite proxy；生产建议 Nginx）
   ▼
后端服务 agent/service.py（Python 3 标准库 ThreadingHTTPServer，端口 8787）
   │                    │
   │                    ├── SQLite（WAL 模式）：账号/审批/建议/企业数据
   │                    ├── 静态 JSON 数据分片（frontend/public/data/）
   │                    └── 本地大模型：Ollama（http://127.0.0.1:11434）
   ▼
本机文件系统（无外部数据库、无云服务）
```

**核心结论（供合规快速预审）：**

| 检查项 | 结论 |
|---|---|
| 外部 CDN / 在线字体 / 公共 JS 库 | ❌ 无，全部资源本地打包 |
| 地图底图与字体 | ✅ 完全离线（本地 .pmtiles 瓦片 + 本地字体 glyphs） |
| 运行期出网请求 | ⚠️ 仅 1 处（「近况分析」联网搜索，可配置/可禁用，见 §4） |
| 大模型调用 | ✅ 本地 Ollama，不经过任何云端 API |
| 数据存储 | ✅ 全部本地（SQLite + JSON 文件），无云上传输 |
| 第三方包许可证 | ✅ 全部 MIT / BSD / Apache-2.0 宽松许可，无 GPL 传染 |
| 已知组件漏洞 | ⚠️ xlsx 0.18.5 存在 2 个公开 CVE（低风险，见 §5.2） |

## 三、后端技术明细（agent/）

### 3.1 语言与依赖

| 项 | 说明 |

### 3.2 功能模块

| 模块 | 文件 | 说明 |

| 登录认证 | auth.py | PBKDF2 加盐哈希 + Bearer Token（24h，落库 sessions 表），注册/审批/建议三业务表 |

| 大模型 | llm.py | **仅对接本地 Ollama**（默认 `http://127.0.0.1:11434`，环境变量可改），无任何云端 LLM API |

### 3.3 数据存储

- SQLite 单文件库（`agent/data/*.db`），WAL 模式，仅本机访问；
- 企业清单/产业链关系为静态 JSON 文件，随前端静态站点分发；
- **无外部数据库、无消息队列、无对象存储、无遥测上报**。

## 四、运行期外部网络访问点（合规重点）

对全部源码及生产构建产物（dist/）做了全量 URL 扫描，运行期会发出**站外请求的只有 1 处功能**：

### 4.1 「周报 · 近况分析」联网抓取（frontend/src/features/report/companyRecent.js）

- **触发**：周报页点击某上市公司「近况分析」按钮时；
- **行为**：经跨域代理请求 `https://cn.bing.com/search?q=...` 公开检索页，抓取企业新闻；
- **代理候选**（代码内置）：`api.allorigins.win`、`corsproxy.io`、`api.codetabs.com`，可用环境变量 `VITE_NEWS_PROXY` 覆盖为自建代理；
- **失败回落**：任一层失败自动回落到本地快照数据（构建期预抓取）或本地舆情数据，页面照常可用，不会报错中断。

**内网处置建议（三选一）：**

1. **最稳妥**：重新构建时设置 `VITE_NEWS_PROXY=http://内网自建代理/`（如无则该功能自动回落本地快照，等效于离线）；
2. 构建后用 Nginx/防火墙直接拦截前端对上述 4 个域名的访问（功能回落快照）；
3. 允许经代理白名单访问 `cn.bing.com`（如内网允许有限的互联网出口）。

### 4.2 无其他出网点

以下常见风险项经扫描确认**均不存在**：

- ❌ Google Fonts / CDN JS / npm CDN 运行时加载
- ❌ 地图在线瓦片（OSM / 高德 / Mapbox / 天地图）
- ❌ 统计埋点 / Sentry / 百度统计等遥测
- ❌ 云端大模型 API（OpenAI / 通义 / DeepSeek 等）
- ❌ 自动更新检查

1. 内网安装 0.20.2+（`pnpm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`）后重新构建；

## 六、内网部署步骤（建议）

**服务器要求**：一台内网 Windows/Linux 主机，无需访问互联网。

### 6.1 前端（纯静态）

1. 在有网的构建机执行 `pnpm install && pnpm build`，得到 `frontend/dist/`（约 480 MB）；
2. 拷贝 dist 至内网服务器，用 Nginx 托管：
   ```nginx
   server {
     listen 8080;
     root /opt/industry-map/dist;
     location /api/ { proxy_pass http://127.0.0.1:8787; }
   }
   ```
3. 首次部署需把 `VITE_NEWS_PROXY` 决策（§4.1）在构建期固化，或由 Nginx 拦截出网。

### 6.2 后端

1. 内网机安装 Python 3.12+ 与 openpyxl（`pip install openpyxl -i 内网镜像`，仅此一个包）；
2. 拷贝 `agent/` 目录（含 data/ 与 knowledge/）；
3. 启动：`python agent/service.py`（可选环境变量 `AGENT_HOST=0.0.0.0`、`OLLAMA_BASE=http://内网Ollama地址:11434`）；
4. 初始管理员 `admin / 112358`，**上线前务必改密**（方法见 agent/README.md）；
5. 防火墙：8787 端口只对内网网段开放；如无大模型需求，无需部署 Ollama。

### 6.3 数据与账号安全

- 所有数据（企业清单、账号、审批记录、用户建议）均在服务器本地 SQLite/JSON，无外传通道；
- 密码存储为 PBKDF2 加盐哈希，不可逆；
- 建议：定期备份 `agent/data/` 目录；生产环境启用 HTTPS（Nginx 证书）。

## 八、开源与授权性质分析（是否需要购买 License）

**结论先行：本项目使用的全部软件均为开源许可，无任何需要付费购买商业 License 的组件。** 但「开源 ≠ 无义务」，有两类**免费但需履行义务**的事项，逐项说明如下。

### 8.2 ⚠️ 重点澄清一：Mapbox 收费问题

行业内常听说「地图库收费」——那指的是 **Mapbox GL JS v2.0+**（改为专有协议、按加载量收费）及 Mapbox 商业服务。本项目使用的是 **MapLibre GL JS**：它是 Mapbox GL v1.13（最后一代 BSD 开源版）的社区分支，**完全开源免费**。注意：**切勿在内网改造时误换成 `mapbox-gl` 官方包**，那才会引入付费协议。

### 8.3 ⚠️ 重点澄清二：底图「数据」采用 ODbL（免费但必须署名）

地图底图瓦片文件（`china-overview.pmtiles` / `shanghai-detail.pmtiles`）下载自 Protomaps 官方构建（`build.protomaps.com`），其底层数据来自 **OpenStreetMap，适用 ODbL 1.0（开放数据库许可）**：

- **使用免费**，无需购买；
- **义务：展示数据署名**（"© OpenStreetMap contributors"）。此前代码中 `attributionControl: false` 未展示署名，已于 2026-11-06 修正为在地图右下角展示（含 ODbL 说明，见 `useMapController.js`）；
- **相同方式共享（ShareAlike）**：仅在对瓦片数据库做修改并**对外再分发**时触发；内网部署、不做二次分发则不涉及；
- 另注意：若系统未来从内网**公开到互联网**，中国境内还需符合《地图管理条例》（互联网地图审图号）——纯内网部署一般不适用，但升级部署范围时应重新评估。

### 8.4 无「开源非商用 / 试用 / 需激活」组件

已逐包核验 `package.json` 的 license 字段与 node_modules 内许可文件，不存在以下类型：

- ❌ 开源但禁止商用的许可（AGPL、CC-NC、SSPL 等）——未使用；
- ❌ 试用版 / 社区版功能阉割需升级付费的组件——SheetJS 付费版仅含官方技术支持与高级解析器，本项目功能用 CE 版已完全覆盖；
- ❌ 需序列号 / 激活码 / 按量计费的服务——地图、模型、存储全部本地化。

### 8.5 采购/评审建议口径

1. **软件授权**：零采购成本；建议留存本清单 + 各包 LICENSE 文件随归档（构建产物内已含）。
2. **数据署名**：地图页右下角已展示 OSM 署名，验收时确认未被关闭即可。
3. **唯一可选付费项**：SheetJS 官方企业支持、Protomaps 商业支持——均为非必需增值服务，不采购不影响功能与合规。

## 附录：2026-11-16 底图升级为 OSM 街道级（与上文冲突处以本节为准）

Natural Earth 底图只有国界/省界/城市点，放大后没有街道，无法支撑「按厂址定位企业」的使用场景。经与业务确认，底图重新引入 OpenStreetMap 街道级矢量瓦片。

**现状：**

1. **底图分层**：
   - 街道级细节：OSM 矢量瓦片 `frontend/public/map/osm-china.pmtiles`（Planetiler 基于 OpenMapTiles schema 从中国 OSM 数据构建，含道路/水系/建筑/地名，z0–z14）。
   - 海面/邻国陆地/湖泊/河流/城市点：仍为 Natural Earth（公有领域）GeoJSON，作为低层级底衬。
   - 国界/省界：仍为国内口径 `china-provinces.geojson`，**OSM 自带的 boundary 与 country/state 标注在样式中有意不渲染**，台湾标注逻辑沿用 `cities.geojson` 的 `taiwan` 属性。
2. **许可与义务**：OSM 数据适用 **ODbL 1.0**。
   - 免费、可商用、可离线自托管；
   - **必须署名**：地图右下角显示「© OpenStreetMap contributors」（`attributionControl` 的 `custom` 文案，见 `useMapController.js`），验收时确认未被关闭；
   - ShareAlike 仅在对瓦片数据库修改并**对外再分发**时触发；内网自用不涉及；
   - 瓦片由本项目自行构建（Planetiler，Apache-2.0），不依赖 Protomaps 商业支持，无采购项。
3. **构建方式**：`tools/basemap-build/` 下用 Planetiler 从 `china-latest.osm.pbf` 生成，构建期需要联网下载 OSM 数据与三个辅助数据源（水系面、湖泊中心线、Natural Earth 矢量库）；**运行期零外网请求**，内网只读取本地 pmtiles 文件。
4. **体积影响**：pmtiles 文件会随安装包进入镜像，安装包与镜像体积相应增大（见 release 目录内实际产物大小）。
5. **风险提示**：OSM 中国数据由志愿者维护，部分偏远地区路网不如商业地图完整；如后续对外发布，仍需按《地图管理条例》评估互联网地图审图号要求。
